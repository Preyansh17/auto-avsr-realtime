# Re-voicing augmentation (design B), patient split_v1

Question: does a synthetic copy of each real training clip, generated by the finetuned Higgs v2 adapter with **that
same clip as its reference** (same speaker, same sentence, the real recording as the prompt), lower Whisper test WER
on the 40 split_v1 test sentences? Asked by the user on 2026-10-20 ("for sentences where we already have a specific
ground truth we can use that as a reference to generate better and similar synthetic clips"; design B = ASR
augmentation, chosen over a similarity-only test because only 9 held-out sentences have repeated recordings).

Cluster: `/scratch/pa2753/asr_aug/revoice/{code,data,logs}`; adapter `/scratch/pa2753/higgs_ft_clean/runs/B_r64/epoch_08`;
audio `/scratch/pa2753/gen_runs/FT_RV_clean_c{1,2}`.

## Pipeline

1. `tts_clean.sbatch`: TTS split with every ASR val **and** test sentence removed (`tts_finetune/prep_data.py` default,
   `--asr-holdout val,test`), then the patient B recipe (r64, alpha 128, lr 1e-4, 15-epoch cosine) stopped at epoch 8,
   fixed in advance as for B_r64. Fixes the val contamination of the first study (37/40 ASR val clips were TTS train).
2. `make_plan.py`: for each of the 314 ASR-train clips, 2 copies (seeds differ), reference = the clip itself (16 kHz
   split_v1 wav + its manifest transcript), text = the same transcript. Asserted: adapter split excludes ASR val/test,
   every text is ASR-train, none is in ASR val/test.
3. Generation: `tts_finetune/final_gen.sbatch` stripes over `data/plan.json`.
4. `filter_rv.py collect`, `judge_rv.sbatch` (real-only Whisper R seed 1 on real val + all re-voiced clips),
   `filter_rv.py score`.
5. `make_mix.py --arm V1|V2` (asr_aug), `whisper_aug.sbatch` via `whisper_launch.sh` (TIME=02:30:00).

## Pre-registered (written 2026-10-20, before the adapter finished training and before any re-voiced clip existed)

- **Filter** (kept only if all pass): duration / own source clip duration in [0.5, 2.0] and <= 15 s; speech fraction
  >= 5th percentile of real ASR-train clips; judge WER and insertions <= 95th percentile of the judge on real ASR val.
- **Arms.** R = existing real-only runs, seeds 4-10 (2026-10-13, same `whisper_aug.sbatch` and recipe). **V1 = real +
  314 re-voiced clips** (one kept copy of each source clip where available; if fewer than 314 sources have a kept copy,
  the remainder comes from second copies). V2 = real + 628 (both copies), exploratory.
- **Seeds.** V1: 4-10 (7, paired by seed number with R). V2: 4-6 (3, no claim).
- **Primary test.** Test WER on all 40 test clips, V1 - R, val-selected `best/`. Seed-level two-sided Welch t-test on
  the 7 vs 7 per-seed corpus WERs, and a sentence-level paired bootstrap (errors averaged over seeds per sentence,
  10000 draws) 95% interval. "Helps" only if Welch p < 0.05 **and** the interval lies below 0.
- **Agreement requirement.** A "helps" claim also needs the final-epoch checkpoint (val-free) to show delta < 0 with its
  bootstrap interval below 0.
- **Secondary, no claim:** V2; known-word (36) vs unseen-word (4) subsets; filter pass rates; re-voiced vs source
  duration ratio. A two-level bootstrap is not used (shown conservative, 2026-10-16).
- **Nemotron** (after the LR probe in `asr_aug/nemotron_lr.sbatch` fixes the effective learning rate): R vs V1 with the
  corrected schedule, seeds 1-3, best and final epoch, same tests, secondary.
- Power: R's seed sd is ~1.5 pp on 40 sentences. Simulated Welch 7 vs 7 power is 0.45 for 2 pp and 0.79 for 3 pp
  (review design-1, 2026-10-20), so only effects of ~3 pp or more are expected to be resolvable.

**Amendment 1 (2026-10-20, before the adapter finished and before any re-voiced clip existed).** The design review
found that every earlier Whisper run trained with the decoder prompt `<sot><sot><notimestamps>` but decoded with
`<sot><en><transcribe><notimestamps>` (`whisper_finetune.py` collator; fixed as `--label-prefix lang_task`). The
existing R runs carry the bug, and its effect may differ by arm (hyp casing rates differ by arm). Both arms of this
study are therefore trained with the fixed recipe: **R_lt and V1_lt, seeds 4-10**, `LABEL_PREFIX=lang_task RUN_TAG=lt`
(run dirs `whisper_{R,V1}_lt_seed*`). V2_lt seeds 4-6 stays exploratory. The old R seeds 4-10 are not used as the
reference. The tests, filter and agreement rule above are unchanged.

**Amendment 2 (2026-10-20, after the adapter, before generation).** split_v1 is split by recording, so 11 of the 314
ASR-train clips say one of 10 ASR val sentences (0 test). Re-voicing them would add synthetic copies of val sentences
and bias val-based checkpoint selection toward V, so `make_plan.py` skips them: 303 source clips, 606 generated.
V1 stays real + 314 (one kept copy per source, the remainder from second copies). V2 becomes **Vall** = real + every
kept re-voiced clip (at most 606, not 628), still exploratory.

**Amendment 3 (2026-10-21, after generation, before the filter ran and before any V run).** Two results that
arrived after amendment 1:
- The fixed Whisper recipe is worse. R_lt test WER is 11.06 +- 3.24 vs 7.43 +- 1.59 for legacy R (seeds 4-6,
  bootstrap [+0.90, +6.76]). Re-decoding the old best/ checkpoints with their trained prompt costs every arm WER, and
  costs R the most (patient test +2.82 R vs +0.64 to +1.86 for the augmented arms; `asr_aug/prefix/`). So the
  accidental mismatch both regularises and favours R.
- The corrected Nemotron schedules do not beat the old one. Seeds 1-3, test, best: flat 1e-5 11.21 +- 0.78,
  cosine 1e-4 10.76 +- 3.23, old 10.61 +- 0.68. Final epoch: 13.45 and 13.75 vs 11.21. Mean in-training val best is
  tied (0.170 / 0.170).

Changes, decided with the user:
- Whisper keeps R_lt vs V1_lt (seeds 4-10) as the **primary** test. **Secondary, same tests:** V1 with the legacy
  recipe (`whisper_V1_seed4-10`) vs the existing legacy R seeds 4-10. If the two disagree, report both; no "helps"
  claim from the secondary alone.
- Nemotron keeps the old schedule (`LR_SCHEDULE=noam`, effective 1e-6). V1 seeds 1-3 are compared with the existing
  Nemotron R seeds 1-3, which also avoids rerunning R.
