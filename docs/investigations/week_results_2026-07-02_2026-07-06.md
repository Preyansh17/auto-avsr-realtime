## TL;DR

- Wired the last loose ends in the Whisper pipeline: `--train-decoder`/`TRAIN_DECODER` through the sbatch, `--seed`/`SEED` for reproducible runs (methodology established last week: unseeded comparisons are meaningless at this data scale).
- Took Nemotron (`nvidia/nemotron-speech-streaming-en-0.6b`, cache-aware FastConformer-RNNT) from "code complete, never run" to a genuinely working, seeded, validated pipeline — **16+ real bugs** fixed along the way, spanning missing deps, NeMo config-schema drift, a package-split import bug, a scheduler crash, a hard GPU segfault, and a silent data-wiring bug that made all 6 first real runs collapse to garbage.
- **Root cause of the segfault marathon:** `numba-cuda` — a companion package required since numba 0.59 for CUDA target support — was never installed. Diagnosed via `NUMBA_ENABLE_CUDASIM=1` (numba's CPU simulator), which turned an uncatchable segfault into a clean `AttributeError` and proved numba.cuda's real-GPU path was the crash site.
- **Root cause of the "identical garbage WER" bug:** the pretrained model's saved config defaulted to `text_field="answer"` (some other finetuning convention), but our manifests use `"text"` — every training/validation target transcript was silently missing the whole time, for all 6 first real runs (3 frozen + 3 full-FT seeds, all converged to WER=102.76%, predicting only unknown-token placeholders).
- After the fix: **Nemotron shows the same pattern as Whisper — full finetune beats Green's freeze-first-5 recipe decisively.** Frozen median WER 67.0%, full-FT median WER 35.7% (offline eval, 3 seeds each).
- Built the streaming (cache-aware, chunked, carried-state) eval that was missing — the offline `transcribe()` eval only gives an upper-bound number for a model whose entire design point is chunked/causal streaming inference. Streaming eval script was a first attempt at NeMo's cache-aware streaming API (no local NeMo install to verify against) — smoke-tested clean on the first try, no fixes needed.
- **Streaming WER essentially matches offline WER for both configs** — frozen streaming median 66.5% (offline 67.0%), full-FT streaming median 35.7% (offline 35.7%, exact tie). Chunked/causal decoding is not costing WER here, a genuinely good result for the AV Emformer comparison.
- Ran the full-FT SpecAugment ablation (missing from the first batch): no-SpecAugment seeds gave 35.68% / 35.68% / 33.51% → median **35.68%**, an **exact tie** with the SpecAugment-on median (35.68%). Confirmed the `SPECAUG=0` flag genuinely took effect (`SpecAugment: DISABLED (ablation)` printed in each log) and the two 35.68%-seed hyps files aren't duplicates (`diff` shows they differ) — a real, dead-flat tie, not a bug. Unlike Whisper (where SpecAugment's effect varied by model size — helped medium/turbo, hurt large-v3), Nemotron shows no measurable effect either way.
- Added Nemotron's first-ever real WER-based checkpoint selection (`SaveBestWER` callback), then gave it the same honest three-way train/select/test treatment that overturned a headline Whisper conclusion (see the other results file's §28-29). **Unlike Whisper, no bias found** — Nemotron never had best-of-N selection to begin with, so there was nothing to correct; new numbers (frozen-legal 70.5%, full-FT-legal 33.3%, frozen-merged 69.2%, full-FT-merged 31.7%) are within a few points of the old last-epoch numbers either direction, consistent with ordinary variance (§15).

## What we did

### 1. Whisper — remaining flags wired
`--train-decoder`/`TRAIN_DECODER` env threaded through `slurm/whisper_finetune.sbatch` (needed for the full-finetune configs used throughout last week's Whisper sweep, previously only settable by hand). `--seed`/`SEED` added to `whisper_finetune.py` (`transformers.set_seed` + `Seq2SeqTrainingArguments(seed=, data_seed=)`), matching the seeding convention established for the AV Emformer and now Nemotron.

### 2. Nemotron env setup — same class of gaps as Whisper, worse
Standalone `nemo_asr` conda env built from `requirements-nemotron.txt`. Hit the same missing-`sentencepiece` and missing-`torchaudio` gaps as the Whisper env, plus one NeMo-specific new one: newer `torchaudio` moved `load()`/`save()` entirely onto `torchcodec`, which needs **real FFmpeg shared libraries** (`libavutil.so` etc.), not just a pip package. Fixed via `conda install -c conda-forge "ffmpeg<8"` + `pip install torchcodec`. `torchaudio.info()` no longer exists on this stack at all — already handled gracefully by an existing try/except fallback to a full `torchaudio.load()` decode in `make_nemo_manifest.py`.

### 3. Lhotse dataloader config schema — bucketing keys rejected one at a time
The pretrained model's saved `train_ds`/`validation_ds` config has several bucketing-related keys (`num_buckets`, `bucket_buffer_size`, `bucket_duration_bins`, `bucket_batch_size`, `batch_duration`, `max_tps`, `shuffle_buffer_size`) set to `null`. Newer NeMo's `LhotseDataLoadingConfig` schema types these as non-Optional ints/floats, so `OmegaConf.merge` rejects each `None` one at a time — fixing `num_buckets` alone just surfaced `bucket_buffer_size` next. Final fix: delete all the null bucketing keys entirely so the dataclass schema's own defaults fill in (bucketing is a throughput optimization for large multi-hour corpora, irrelevant for this ~268-clip set).

### 4. `lightning.pytorch` vs `pytorch_lightning` — package split
NeMo's `ASRModel` inherits from `lightning.pytorch.core.module.LightningModule` (the unified `lightning` package), **not** the standalone `pytorch_lightning` package — confirmed via `ASRModel.__mro__` on the installed `nemo_toolkit==2.7.3`. Despite similar naming and shared history, the two packages define distinct, non-aliased `LightningModule` classes. Using the wrong import made `pl.Trainer.fit()` raise `TypeError: model must be a LightningModule ... got EncDecRNNTBPEModel`. Fixed: `import lightning.pytorch as pl`.

### 5. Scheduler crash — Lhotse's lazy dataset has no `__len__`
NeMo's scheduler setup auto-derives `max_steps` from `len(train_dataloader.dataset)` when not given explicitly. Lhotse's dynamic/streaming dataset (`LhotseSpeechToTextBpeDataset`) has no `__len__` by design (lazy duration-based sampling), so this crashed with `TypeError: object of type 'LhotseSpeechToTextBpeDataset' has no len()`. Fixed by computing `max_steps` ourselves from the manifest's line count (`steps_per_epoch = num_train_examples // batch_size`, `max_steps = steps_per_epoch * epochs`) and setting `model.cfg.optim.sched.max_steps` explicitly so NeMo never needs the dataset length.

### 6. RNNT loss backend — misdiagnosis, then real fix
An unpinned `numba` (nemo_toolkit doesn't pin it itself; pulled in transitively via librosa/resampy) resolved to 0.66.0 and crashed with a numba internal type-inference error mid-training on the CUDA-JIT'd RNNT loss kernel (`warprnnt_numba`). First attempt: swap `loss_name="pytorch"` to avoid numba entirely — **wrong assumption**, it's still numba-JIT'd under a different module (`nemo/collections/asr/parts/numba/rnnt_loss/rnnt_pytorch.py`), didn't help. Reverted to NeMo's actually-tested default (`warprnnt_numba`) and instead pinned `numba==0.60.0` (a version vetted against NeMo's kernels, installed after `nemo_toolkit` so its own resolution doesn't immediately overwrite the pin).

### 7. The segfault marathon
After the numba pin, training crashed with a **hard segfault** (SIGSEGV, no catchable Python exception) at the eval→train mode transition following sanity-check validation. Ruled out, one at a time, by reproducing the *identical* crash under each change: precision (bf16→fp32), CUDA graph decoder disable, `num_workers` 2→0, forcing `foreach=False, fused=False` on AdamW. `CUDA_LAUNCH_BLOCKING=1` + `python -X faulthandler` pointed at `torch/optim/adam.py:227` — a **red herring** (async CUDA corruption surfacing downstream, not the real site). The actual diagnosis: `NUMBA_ENABLE_CUDASIM=1` (numba's CPU simulator, routes around real CUDA) turned the segfault into a clean, catchable `AttributeError: module 'numba.cuda' has no attribute 'default_stream'` — proving numba.cuda's real-GPU code path was the crash source. Root cause: **`numba-cuda`**, a separate companion package required since numba 0.59 for CUDA target support, was never installed (not pulled in automatically by `numba` or `nemo_toolkit`). `pip install numba-cuda` fixed the segfault entirely; the CUDA graph decoder disable and non-fused AdamW changes from the earlier (wrong) hypotheses were kept in the code as harmless no-ops, not because they were the actual fix.

### 8. sbatch template rewrite + LD_LIBRARY_PATH
`slurm/nemotron_finetune.sbatch` was written before the real working env existed and assumed an obsolete singularity+overlay pattern — rewrote it to match the actual bare-venv pattern used by Whisper. Added `--seed`/`SEED` support to `nemotron_finetune.py` (was missing entirely). First real 3×2-seed batch launch then failed identically across all 6 jobs at manifest-building: `torchcodec` couldn't `dlopen()` `libavutil.so`. Root cause: `conda activate` normally sets `LD_LIBRARY_PATH` to include `<env>/lib`; the sbatch calls the venv python directly (no activate, deliberately, to dodge module-load complexity), so it was never set — masked during earlier interactive login-node testing (leftover shell env state from installing ffmpeg there), only surfaced on a genuinely fresh compute node. Fixed: explicit `export LD_LIBRARY_PATH="${NEMO_ENV}/lib:${LD_LIBRARY_PATH:-}"`.

### 9. The data-wiring bug — all 6 real runs collapsed to garbage
After the `LD_LIBRARY_PATH` fix, all 6 real runs (3 frozen + 3 full-FT seeds) converged to an **identical** WER (102.7568%), predicting only `⁇` (unknown-token placeholders) for every input regardless of seed or freeze config — a strong signal of a data bug, not a training-dynamics one. Diagnosed from the model's own printed config: `text_field: answer`. NeMo's Lhotse dataloader was reading a manifest field called `"answer"` that doesn't exist in our manifests (which use `"text"`, written by `make_nemo_manifest.py`) — every training/validation example's target transcript was silently missing the entire time. Fixed: `model.cfg.train_ds.text_field = "text"` and `model.cfg.validation_ds.text_field = "text"`. Verified via a 5-epoch smoke test showing real word predictions ("And") instead of garbage before relaunching the full seeded batch.

### 10. Real seeded results — full-FT beats Green freeze, same as Whisper
Reran the 3×2-seed batch (frozen vs full-FT, seeds 1-3) with the fix. Results (offline `transcribe()`, legal_only 30-clip val set, shared normalizer):

| config | median WER |
|---|---|
| Green freeze (first 5 encoder layers) | 67.03% |
| **Full finetune** | **35.68%** |

Same pattern as every Whisper size tested last week: Green's freeze-first-N recipe, imported from a different paper's dysarthric-ASR setup, underperforms full finetune substantially on this architecture too.

### 11. Checkpoint selection audit — no WER-based "best" tracking
User asked how Nemotron's best checkpoint gets chosen. Checked `nemotron_finetune.py`: `enable_checkpointing=True` is just Lightning's default (no `monitor=`), and `model.save_to(out)` is called unconditionally right after `trainer.fit()` returns — saving whatever the **last epoch** produced. This matches the AV Emformer's "merge last epoch" approach, not Whisper's `load_best_model_at_end=True, metric_for_best_model="wer"` approach. Flagged as a risk given the AV Emformer's own history of last-epoch-selection being tied to large run-to-run variance (see last week's file, §10-13) — not yet acted on, but the 3-seed spread we do have (67.0/66.5/70.8% frozen; 34.1/35.7/35.7% full-FT) is fairly tight, which is at least reassuring evidence against a bad case.

### 12. Streaming eval — built from scratch, smoke-tested clean
User asked whether a streaming version of the eval existed — it didn't; `nemotron_eval.py`'s own docstring flagged this as a known follow-up. Built `asr_baselines/nemotron_streaming_eval.py` using NeMo's own cache-aware streaming utilities (`CacheAwareStreamingAudioBuffer` for chunk framing, `model.conformer_stream_step()` for the carried-state decode loop across `cache_last_channel`/`cache_last_time` state) rather than reimplementing chunking/caching — matching the pattern from NeMo's own `examples/asr/asr_cache_aware_streaming/speech_to_text_cache_aware_streaming_infer.py`. Written without a local NeMo install to verify the exact API against (no NeMo on this machine) — deployed as a first attempt and smoke-tested on `nemotron_frozen_seed1` via a new standalone `slurm/nemotron_streaming_eval.sbatch` (runs against any already-finished checkpoint, no retraining needed). **Passed on the first try, no fixes needed**: `N=30 streaming WER=0.6649 ... RTF=0.026`, close to and consistent with the offline 67.0% number.

### 15. Real checkpoint selection added, then a genuine three-way split — no Whisper-style bias found
§11 flagged Nemotron as last-epoch-only with zero WER-based checkpoint selection, unlike Whisper's `load_best_model_at_end`. Separately, the Whisper investigation (see `results/week_results_2026-06-23_2026-07-01.md` §28-29) found that Whisper's best-of-30-epoch selection — chosen AND reported on the same val set — was a real, large bias (~4-6pp, enough to reverse a headline "large-v3 is best" conclusion once corrected with an honest three-way train/select/test split). Went back to give Nemotron the same fair test, in two steps.

**Step 1 — add real selection.** `asr_baselines/nemotron_finetune.py` gained a `SaveBestWER` Lightning callback: NeMo's RNNT models already compute `val_wer` every validation epoch (`rnnt_models.py`'s `multi_validation_epoch_end`), but nothing consumed it — `model.save_to()` was called unconditionally after `trainer.fit()`, always the last epoch. The new callback watches `trainer.callback_metrics["val_wer"]` and calls NeMo's own `model.save_to()` (not a Lightning `.ckpt`, to avoid a separate, less-proven restore path for a NeMo `ModelPT`) whenever it improves, saving `nemotron_best.nemo`. Built to degrade safely — if `val_wer` never appears in `callback_metrics` (untested on this NeMo/Lightning version pairing going in), it prints a clear `WARNING` and the caller falls back to last-epoch-only, no silent wrong behavior. A 3-epoch smoke test confirmed it actually engages: `[best] epoch=1 val_wer=0.9135`, `[best] epoch=2 val_wer=0.8865`, both correctly saved.

**Step 2 — three-way split.** `slurm/nemotron_finetune.sbatch` gained a `TEST_FILE` var (mirrors Whisper's, defaults to `VAL_FILE` for back-compat) — builds a `test_manifest.jsonl` from it and evaluates `nemotron_best.nemo` (falling back to `nemotron_patient.nemo` if selection never engaged) against that manifest for the final reported number, keeping `VAL_FILE` purely for selection. Reused the exact same label-CSV splits already built for the Whisper three-way experiment: legal_only (train=238 / val=30-selection / test=30-held-out) and merged (train=314 / val=40-selection / test=40-held-out). Ran frozen (Green) and full-FT, both datasets, 3 seeds each — 12 real 30-epoch runs:

| config | seed1 | seed2 | seed3 | **median** |
|---|---|---|---|---|
| frozen, legal_only | 71.58% | 68.85% | 70.49% | **70.49%** |
| full-FT, legal_only | 35.52% | 32.24% | 33.33% | **33.33%** |
| frozen, merged | 69.16% | 69.16% | 69.16% | **69.16%** |
| full-FT, merged | 31.72% | 31.72% | 34.36% | **31.72%** |

(frozen-merged's identical-looking 69.16% three times was sanity-checked — `diff` confirms the three `test_hyps.tsv` files are non-identical, a real coincidence in the rounded number, not a duplicated run, same pattern as §14.)

**Comparison to the old last-epoch-only numbers:**

| config | old (last-epoch, no held-out split) | new (honest 3-way) | delta |
|---|---|---|---|
| frozen, legal_only | 67.03% offline / 66.49% streaming | 70.49% | +3.5-4pp worse |
| full-FT, legal_only | 35.68% offline / 35.68% streaming | 33.33% | −2.35pp better |

**No Whisper-style bias found.** The deltas here (a few points either direction) are consistent with ordinary seed/data variance, not the systematic 4-6pp inflation that reversed Whisper's headline conclusion. This makes sense in hindsight: Whisper's bias came specifically from selecting AND reporting on the *same* set; Nemotron never did that (it had no selection at all before this section), so there was no matching bias to uncover — adding real selection here is a genuine improvement (better checkpoints, e.g. full-FT/legal_only improved 2.35pp) but not a correction of an inflated number.

**Full-FT still crushes frozen on both datasets** (33.3% vs 70.5% legal_only, 31.7% vs 69.2% merged) — consistent with every prior finding this investigation. Merged is slightly better than legal_only for full-FT here (31.7% vs 33.3%) — a much smaller merged-data benefit than Whisper saw (where merged full-FT was roughly 3-5x better than legal_only, see the other results file's §29), suggesting Nemotron's smaller/differently-pretrained encoder doesn't benefit from the extra merged clips nearly as much as Whisper's larger pretrained models did.

### 16. Error analysis + beam decode — blank collapse was ~half the error mass, mostly recoverable

Ran per-utterance error analysis (S/D/I breakdown) on the §15 honest-3-way full-FT test hyps, all 6 seeds (3 legal + 3 merged). Deletions dominated (17.5-25.6% of words) far more than substitutions (8.4-14.2%) or insertions (~0.5%), and roughly **45% of total error mass came from completely empty hypotheses** — 4-6 clips per run outputting nothing. Cross-checked against the best Whisper checkpoint on the identical clips: Whisper decoded them fine (6/11 verbatim, rest near-perfect), and the empty clips were deterministic — the same clips came back empty across all 3 seeds, not seed noise. Diagnosis: classic RNNT blank-token collapse (encoder confident on blank every frame), not an audio-quality problem — matches the AV Emformer's own early "silent output" failure mode, same RNNT family.

Added `--decoding {greedy,greedy_batch,beam,maes}` / `--beam-size` to `nemotron_eval.py` (`model.change_decoding_strategy`, same `use_cuda_graph_decoder=False` workaround already used in finetune) and reran all 6 §15 checkpoints (`nemotron_best.nemo`) with `maes` beam search, width 8 (plus one width-4 spot check per dataset):

| Dataset | Seed | Greedy | maes beam=8 | maes beam=4 |
|---|---|---|---|---|
| legal | 1 | 35.52% | 32.79% | — |
| legal | 2 | 32.24% | 31.15% | — |
| legal | 3 | 33.33% | 32.24% | 32.79% |
| **legal median** | | **33.33%** | **32.24%** | |
| merged | 1 | 31.72% | 22.91% | 25.99% |
| merged | 2 | 31.72% | 25.11% | — |
| merged | 3 | 34.36% | 23.35% | — |
| **merged median** | | **31.72%** | **23.35%** | |

**Merged: −8.4pp median, every seed improves 6.6-11pp** — all 5 deterministic-empty clips decode under beam (2 perfect, 3 partial), deletions drop 22.9%→7.0%. **Legal: −1.1pp median, smaller but every seed improves** — beam recovers 3/5 empty clips but also flips ~7 previously-correct greedy clips to worse beam hypotheses on this split, largely offsetting the empty-clip gain. Width 8 beat width 4 on both spot-checked seeds, no sign of over-aggression yet. RTF unaffected (0.025-0.039, still offline `transcribe()` — beam gain has NOT been verified in the cache-aware streaming decode path, which decodes greedy inside `conformer_stream_step` and would need separate wiring/validation to confirm it transfers).

Revised full-FT honest-3-way leaderboard entry: **legal 32.2%** (was 33.3%), **merged 23.4%** (was 31.7%). Still 20+pp behind streaming Whisper (9.3%/4.0%) — beam ate the cheap, structural half of the error (blank collapse); the rest is substitutions/garbage on genuinely harder clips, which is a robustness problem beam search can't fix (next lever: LR/epoch sweep, see Open/next).
